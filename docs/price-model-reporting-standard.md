# 서울 Airbnb 가격 모델 보고서 작성 기준

> **상태: 초안.** 이 문서는 `price-model-learning-report-ko.md`를 새로 만들거나 수정할 때 지켜야 할 기준이다. 사용자의 피드백에 따라 계속 보완한다.

## 1. 보고서의 목적과 독자

보고서는 통계학 비전공자도 다음 질문을 순서대로 이해하도록 돕는다.

1. 무엇을 예측하는가(Y)?
2. 어떤 숙소 특성(X)을 왜 후보로 삼고, 어떤 특성은 왜 제외했는가?
3. X를 어떤 규칙으로 숫자·범주형 피처로 만들었는가?
4. 여러 모델 중 무엇을 선택했고, 그 이유는 무엇인가?
5. 새 숙소에 대한 예측력은 어느 정도이며, 어디까지 믿을 수 있는가?

보고서는 클라이언트에게 설명하는 문서다. 내부 DB 테이블명, 컬럼명, 실행 과정, 코드 구현은 독자가 해석에 꼭 필요한 경우에만 짧게 괄호로 언급한다. 기본 설명은 비즈니스 언어와 구체적 사례를 사용한다. 특히 **X 변수 표와 본문은 내부 컬럼명이 아니라 변수의 의미를 자연어로 쓴다.** 예를 들어 `room_type` 대신 “임대 방식”, `x_km`·`y_km` 대신 “동서·남북 방향 좌표”라고 쓴다. 로그 변환처럼 해석에 필요한 처리만 자연어 괄호로 덧붙인다.

## 2. 고정된 보고서 흐름

아래 순서를 기본 구조로 유지한다. 절을 새로 만들거나 합칠 때는 각 절의 질문이 사라지지 않는지 확인한다.

1. **프로젝트 목적과 Y** — 가격 데이터를 어떻게 1박 단위로 맞췄는지와 로그 변환 이유를 설명한다.
2. **데이터 수집·분석 단위·데이터 품질** — 크롤링 통합, 숙소당 1행, 서울 범위, 결측·가격 오류·통계 플래그를 설명한다.
3. **후보 X 변수 탐구와 제외 근거** — 후보군과 제외 기준을 표로 제시한다.
4. **피처 엔지니어링** — 객실, 편의시설, 수용 인원, 위치, 군집, 좌표를 각각 정의하고 결측 처리 원칙을 설명한다.
5. **모델 후보와 CV 비교** — 후보 모델·전처리·교차검증·선택 규칙을 설명한다.
6. **최종 모델과 최종 X** — 선택 모델의 작동 원리, 설정, 전체 X 목록, 해석 범위를 제시한다.
7. **모델 검증용 숙소 데이터 평가** — 같은 검증 숙소에 대한 기준/수정 모델의 달러 단위 오차를 비교한다.
8. **한계·재현성** — 시간·숙박일·가격 구성요소 차이, 공간 일반화, 재현 명령과 무결성 검사를 남긴다.
9. **모델 사용 결과와 정확도 판단** — 검증 숙소에 실제로 적용한 예측 결과를 보여주고, 독자가 사용 목적에 비추어 정확도를 판단하게 한다. 이 절은 보고서의 마지막 절이다.

`PRICE_UNIT_ERROR` 제거와 기준/수정 모델 비교는 중요하지만 보고서의 주제가 아니다. 각각 2절의 데이터 품질과 7절의 모델 검증에 둔다.

## 3. 읽기 쉬운 설명 원칙

- 통계 용어는 첫 등장 시 **무엇인지 → 왜 쓰는지 → 이 보고서에서 어떻게 읽는지** 순서로 설명한다.
- 로그 변환, 교차검증, MAE, RMSE, MAPE, 중앙 절대 오차, 편향, 결정 트리, 부스팅은 수식보다 직관을 먼저 설명한다.
- 한 문단은 하나의 질문에 답한다. 내부 약어와 영문 변수명만으로 문장을 시작하지 않는다.
- 최종 X 목록은 “최종 입력 특성”이라는 제목으로 제시하고, 모든 항목을 사람이 이해할 수 있는 자연어로 쓴다. 코드·DB 대응명은 본문 표에 나열하지 않는다.
- 표에는 숫자만 나열하지 않고, 바로 앞이나 뒤에 독자가 읽어야 할 방향과 한계를 쓴다.
- “증명”, “유의미”, “원인”, “독립 기여”, “프로덕션 준비 완료”는 검정·설계·근거가 있을 때만 쓴다. 관찰 결과라면 “이 표본에서 더 낮은 오차를 보였다”처럼 쓴다.

## 4. 시각자료 기준

각 분석 단계에는 그 단계의 질문에 답하는 시각자료를 포함한다. 그림은 장식이 아니며, 바로 앞이나 뒤의 문단에서 무엇을 읽어야 하는지 설명한다.

| 단계 | 필수 시각자료 | 독자가 확인할 질문 |
| --- | --- | --- |
| 데이터 품질 | 가격 분포·3×IQR·오류 등록 그림 | 통계 플래그와 도메인 오류 등록은 어떻게 다른가? |
| 위치 X | 투영 좌표·K=5 군집 산점도 | 좌표와 군집은 어떤 공간 표현인가? |
| 위치 X | **서울 25개 구 지도 위 K=5 군집별 숙소 점 지도** | 다섯 군집은 서울에서 실제로 어떻게 분포하는가? |
| 모델 비교 | 후보 모델·피처셋 CV 그림 | 어떤 후보가 어떤 척도에서 선택됐는가? |
| 최종 검증 | 기준/수정 모델의 외부 오차 분포·지표 차이 그림 | 모델 검증용 숙소 데이터에서 오차가 어떻게 달라졌는가? |

지도는 기존 `cluster_id`를 색으로 재현해야 하며, 지도 제작 중 새 군집을 계산하면 안 된다. 행정구역 경계는 위치 맥락을 위한 배경이며 모델의 가격 효과를 뜻하지 않는다. 그림의 숫자·범례·주석은 현재 DB 결과에서 계산하고 하드코딩하지 않는다.

## 5. 근거와 측정 기준

- Y의 정의, X의 목록, 모델 설정, CV 지표, 외부 평가 지표는 실행 결과와 일치해야 한다.
- 기준 모델과 수정 모델을 비교할 때 검증 listing ID, 관측 가격 정의, 지표 분모를 동일하게 유지한다.
- MAPE는 분모가 무엇인지, USD 지표는 어떤 1박 가격 정의인지 본문에 쓴다.
- 이력 학습 가격과 모델 검증용 숙소 데이터 가격이 모두 1박 기준인지 확인한다. 가격 구성요소가 다를 가능성은 한계에 명시한다.
- 이미지·표·서술의 수치가 서로 다르면 보고서를 고치기 전에 데이터와 생성 코드를 먼저 확인한다.

## 6. 보고서 마지막: 모델 사용 결과와 정확도 판단

마지막 절은 모델을 실제로 사용했을 때 무엇이 나오는지 보여준다. 독자가 모델을 “정확하다” 또는 “부정확하다”라고 단정하기보다, 자신의 가격 의사결정에 충분한 수준인지 판단할 수 있어야 한다.

필수 내용은 다음과 같다.

1. **사용 방법 한 문단** — 새 숙소의 최종 X를 입력하면 모델이 1박 가격 추정치를 낸다는 점을 평이하게 설명한다. 내부 코드나 직렬화 형식은 본문에 넣지 않는다.
2. **검증 숙소 예측 사례 표** — 모델 검증용 숙소 데이터에서 5~10개를 대표적으로 골라, 숙소 특성 요약·실제 1박 가격·예측 1박 가격·절대 오차를 같은 표에 제시한다. 값이 특히 잘 맞은 사례와 크게 빗나간 사례를 모두 포함하며, 선정 기준을 밝힌다.
3. **전체 오차 요약** — MAE, 중앙 절대 오차, RMSE, MAPE와 392건 커버리지를 달러와 백분율로 함께 제시한다. MAPE는 가격이 낮은 숙소에서 더 크게 보일 수 있음을 설명한다.
4. **독자가 판단할 기준** — 아래 질문으로 가격 참고 도구로서의 적합성을 스스로 판단하도록 돕는다.
   - 일반 숙소에서의 중앙 오차가 내가 허용할 수 있는 가격 차이인가?
   - 평균 오차와 큰 오차(RMSE) 사이의 차이가 큰가? 크다면 일부 숙소에서 예측이 크게 빗나갈 수 있다.
   - 모델이 제시하는 가격을 확정 가격이 아니라, 가격 조사와 재검토를 시작할 범위로 사용할 수 있는가?
   - 숙박일·수집 시점·수수료·세금 정의가 다른 상황에서도 같은 수준의 오차를 기대하려 하는가?
5. **명확한 결론 문장** — 현재 검증 표본에서 보인 오차 수준을 한 문장으로 요약하고, 추천 용도를 "가격 범위 참고"로 한정한다. 단, 산업 전반에 적용되는 보편적 정확도 등급이나 배포 가능성은 주장하지 않는다.

필수 시각자료는 **실제 1박 가격 대 예측 1박 가격 산점도** 또는 **예측 오차 구간별 숙소 수 분포** 중 하나다. 대각선 기준선 또는 0 오차 기준선을 넣어 독자가 맞음과 빗나감을 직관적으로 볼 수 있게 한다. 기존 기준/수정 오차 분포 그림은 유지하되, 이 사용 결과 시각자료를 대체하지 않는다.

## 7. 수정 원칙

- 기존 보고서를 요약본으로 바꾸거나, 관련 없는 문단·표·이미지를 삭제하지 않는다.
- 오류를 고칠 때는 해당 문장, 연결된 표·그림·캡션, 직접 의존하는 한계 문구만 수정한다.
- 구조 변경 전에는 기존 목차·그림·표 목록을 확인하고, 새 구조에도 모두 적절히 배치했는지 점검한다.
- 보고서를 수정한 뒤에는 용어 전수 검색, 수치 대조, 이미지 존재 확인, 링크 확인을 수행한다.
- 지도·그림 생성 코드는 재실행 가능해야 하며, 출처와 데이터 시점을 캡션 또는 재현성 절에 남긴다.

## 9. 슬라이드 및 시각화 디자인 원칙 (Slidev / Presentation)

발표 슬라이드 및 대시보드 시각화는 컨설팅 수준의 높은 시각적 완성도와 절제미를 유지해야 한다. 특히 정보 위계의 왜곡이나 시각적 흐름(Visual Flow)의 단절은 청중의 인지 부하를 극대화하므로 엄격히 통제한다.

### 1) 시각적 흐름(Visual Flow) 및 정보 위계(Hierarchy) 원칙
- **시선의 지그재그 혼란 방지 (Z/F-Pattern Flow)**: 청중의 시선은 [좌측 상단 대제목 → 좌측 컬럼 앵커 → 우측 컬럼 앵커]로 좌에서 우로, 위에서 아래로 물 흐르듯 자연스럽게 이동해야 한다.
- **제목의 물리적 전역 분리 (Full-width Header Separation)**: 슬라이드 대제목(`<h1>`)이 다단 그리드(`two-cols`, `grid-cols-2`)의 특정 컬럼 내부에 종속되는 것을 엄격히 금지한다. 제목이 컬럼 안에 갇히면 좌측 컨텐츠만 아래로 밀려나고 우측 컨텐츠는 천장에 달라붙어 좌우 시작선이 완전히 어긋난다. 대제목은 반드시 상단 전폭 단일 행으로 완전히 분리한다.
- **수평 베이스라인 일치 (Strict Baseline Alignment)**: 2개 이상의 대등한 지표나 대상을 나란히 배치할 때는 상단 시작 좌표(Y값)가 1픽셀의 오차도 없이 동일해야 한다.
- **변수명 최우선 앵커 (Primary Visual Anchor)**: 지표 비교 슬라이드의 주인공은 **변수명(예: 체크인 만족도, 의사소통 만족도 등)**이다. 변수명을 작고 흐릿한 회색 캡션으로 낮추고 엉뚱한 수치만 거대하게 키우는 위계 역전(Inverted Hierarchy)을 금지한다. 변수명이 볼드하고 뚜렷하게 상단에 자리 잡아 인지의 앵커 역할을 해야 한다.
- **정보 대칭성 유지 (Information Symmetry)**: 나란히 배치된 비교 항목 간에는 데이터의 종류, 순서, 타이포그래피 크기가 완벽히 1:1로 일치해야 한다. 한쪽 컬럼에만 주절주절 긴 해설 문단을 붙여 좌우의 여백과 시각적 무게중심(Visual Weight)을 파괴하는 행위를 금지한다.

### 2) 타이포그래피 및 헤드라인 규칙
- **제목 1줄 완결 원칙**: 모든 슬라이드의 제목(`<h1>`)은 **절대 2줄로 줄바꿈되지 않아야 한다**. 글자 수가 많을 경우 문구를 압축하거나 폰트 크기를 조절(`font-size: 1.6rem`, `white-space: nowrap`)하여 1줄에 안정적으로 배치한다.
- **수직 정보 리듬**: `변수명(Headline, 18~20px bold) → 핵심 지표 수치(Metric, 40~48px light/mono) → 판단 기준/상태 라벨(Label, 12~14px)`의 일관된 수직 간격을 유지한다.

### 3) 보더(Border) 및 박스 장식 배제
- **무보더(Zero-Border) 원칙**: 사각 영역에 습관적으로 테두리(`border`, `border-gray-200`)나 그림자(`shadow`)를 둘러 요소를 가두지 않는다.
- **여백 중심 구분**: 컨테이너의 구분은 선이 아니라 **충분한 여백(Whitespace)**과 미세한 명도 차이(아주 연한 단색 배경 `bg-gray-50`) 또는 미니멀한 단일 구분선(`border-b border-gray-100`)만으로 구현한다.

### 4) 악센트 컬러 최소화
- **원 컬러 룰(One Accent Color)**: 슬라이드 내에서 빨강, 파랑, 노랑 등 무분별한 유채색 남발을 엄격히 금지한다.
- 슬라이드의 기본 톤은 차분한 무채색(Slate/Zinc: `text-gray-900`, `text-gray-600`, `text-gray-400`)을 베이스로 유지한다.
- 대비가 필요한 단 하나의 핵심 숫자나 결론에만 절제된 1가지 악센트 컬러를 사용한다.

### 5) 잉여 수치 및 화면 줄글 코멘트 전면 배제
- **탈락 논리에 부합하는 핵심 수치(Primary Metric) 일치**: 슬라이드가 전달하고자 하는 핵심 논거와 대형 강조 수치가 반드시 1:1로 일치해야 한다.
  - 예: '통계적 무의미(유의성 결여)'가 논점인 슬라이드에서는 **유의확률(P-value)**이 대형 숫자로 강조되어야 하며(P > 0.05 탈락 근거 직관화), 설명력 $R^2$를 메인으로 키워 P값의 중요성을 가리는 왜곡을 금지한다.
  - 예: '설명력 결여'가 논점인 슬라이드에서는 **설명력($R^2$)**이 대형 숫자로 강조되어야 한다.
- **부차적 수치 제거 및 시각적 노이즈 차단**: 회귀계수 등 해당 장표의 탈락 논거와 직접 관련 없는 잉여 수치는 과감히 제거하거나 하단 보조 텍스트로 최소화한다.
- **화면 내 줄글/코멘트 전면 배제**: 슬라이드 화면에 장황한 설명 문장이나 해석 문단을 적지 않는다. 화면은 '변수명과 핵심 수치'만으로 극도로 미니멀하게 비우고, 모든 해설과 논거는 100% **발표자 노트(Presenter Notes)**로 넘긴다.

### 6) 모션 및 화면 전환 효과 배제
- **무전환(Zero Transition) 원칙**: 슬라이드 간 넘김 시 불필요한 슬라이딩(`slide-left`), 페이드 등의 모션 애니메이션을 일체 배제한다(`transition: none`).
- 전환 애니메이션으로 인한 시각적 피로도를 없애고, 데이터 보고서의 엄중함과 컨텐츠 전달의 즉각성을 보장한다.

### 7) 페이지 번호 표기 원칙 (Pagination)
- **우측 하단 일괄 표기**: 모든 슬라이드 우측 하단에 `현재페이지 / 전체페이지` 형식(예: `1 / 8`)으로 모노스페이스 미니멀 폰트(`text-[11px] text-gray-400 font-mono`)를 사용하여 조용하게 일괄 표기한다.
- 글로벌 레이어(`global-bottom.vue`)를 활용하여 개별 슬라이드 코드 오염 없이 일관된 위치와 스타일을 유지한다.
